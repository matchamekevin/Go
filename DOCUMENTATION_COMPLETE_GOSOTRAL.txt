## 🔧 MÉTHODES D'INTÉGRATION ET PATTERNS DE DÉVELOPPEMENT

### APPROCHE ARCHITECTURE HEXAGONALE (CLEAN ARCHITECTURE)

Le projet GoSOTRAL suit une architecture hexagonale pour séparer la logique métier des détails d'implémentation :

#### Pattern Repository (Couche Data)
```typescript
// Exemple: User.repository.ts
export class UserRepository {
  static async findByEmail(email: string): Promise<User | null> {
    const result = await pool.query(
      'SELECT * FROM users WHERE email = $1',
      [email]
    );
    return result.rows[0] || null;
  }
}
```

#### Pattern Controller (Couche Présentation)
```typescript
// Exemple: Auth.controller.ts
export class AuthController {
  static async login(req: Request, res: Response) {
    try {
      const { email, password } = req.body;
      // Validation avec Zod
      const validatedData = loginSchema.parse({ email, password });

      // Business logic via repository
      const user = await UserRepository.findByEmail(validatedData.email);

      // Response standardisée
      return res.json({
        success: true,
        data: { user, token }
      });
    } catch (error) {
      return handleError(res, error);
    }
  }
}
```

#### Pattern Service (Couche Business)
Frontend utilise le pattern Service pour centraliser les appels API :
```typescript
// authService.ts - Méthode d'intégration API
class AuthService {
  async login(credentials: LoginCredentials): Promise<AuthResponse> {
    const response = await apiClient.post('/auth/login', credentials);

    // Gestion automatique des tokens
    if (response.data.token) {
      await this.saveToken(response.data.token);
    }

    return response.data;
  }
}
```

### MÉTHODES D'INTÉGRATION FRONTEND-BACKEND

#### 1. Client API Centralisé avec Intercepteurs
**Méthode utilisée**: Instance Axios configurée avec intercepteurs automatiques

```typescript
// Pattern d'intégration: Intercepteurs automatiques
class ApiClient {
  private setupInterceptors() {
    // Request: Injection automatique du token
    this.client.interceptors.request.use(async (config) => {
      const token = await AsyncStorage.getItem(TOKEN_KEY);
      if (token) {
        config.headers.Authorization = `Bearer ${token}`;
      }
      return config;
    });

    // Response: Gestion automatique des erreurs
    this.client.interceptors.response.use(
      (response) => response,
      (error: AxiosError) => {
        if (error.response?.status === 401) {
          this.handleUnauthorized();
        }
        return Promise.reject(this.formatError(error));
      }
    );
  }
}
```

**Avantages de cette méthode**:
- Gestion automatique de l'authentification
- Centralisation des erreurs
- Retry automatique
- Logging uniforme

**Méthode utilisée**: Schémas partagés Frontend/Backend

```typescript

export const loginSchema = z.object({

    next();
```

### PATTERNS DE SYNCHRONISATION TEMPS RÉEL

#### Server-Sent Events (SSE) Implementation
**Méthode choisie**: SSE au lieu de WebSockets pour simplicité et fiabilité

```typescript
// Backend: Event Bus Pattern
class EventBus {
  private clients: Response[] = [];

  addClient(res: Response) {
    this.clients.push(res);
  }

  broadcast(event: string, data: any) {
    const message = `data: ${JSON.stringify({ event, data })}\n\n`;
    this.clients.forEach(client => {
      try {
        client.write(message);
      } catch (error) {
        this.removeClient(client);
      }
    });
  }
}

// Frontend: Auto-reconnection Pattern
const useRealtimeEvents = () => {
  useEffect(() => {
    const eventSource = new EventSource('/realtime');

    eventSource.onmessage = (event) => {
      const { event: eventType, data } = JSON.parse(event.data);
      handleRealtimeEvent(eventType, data);
    };

    // Auto-reconnection
    eventSource.onerror = () => {
      setTimeout(() => {
        // Nouvelle connexion automatique
      }, 5000);
    };

    return () => eventSource.close();
  }, []);
};
```

#### 2. AsyncStorage Pattern pour React Native
**Méthode utilisée**: Couche d'abstraction au-dessus d'AsyncStorage

```typescript
// Pattern: Storage Manager
class StorageManager {
  static async setUser(user: User): Promise<void> {
    try {
      await AsyncStorage.setItem(USER_KEY, JSON.stringify(user));
    } catch (error) {
      console.error('Storage error:', error);
      // Fallback to in-memory storage
      this.memoryStorage.set(USER_KEY, user);
    }
  }

  static async getUser(): Promise<User | null> {
    try {
      const stored = await AsyncStorage.getItem(USER_KEY);
      return stored ? JSON.parse(stored) : null;
    } catch (error) {
      // Fallback to memory
      return this.memoryStorage.get(USER_KEY) || null;
    }
  }
}
```

### MÉTHODES DE SÉCURITÉ IMPLÉMENTÉES

#### 1. JWT avec Refresh Token Pattern
**Méthode utilisée**: Double token (access + refresh) avec rotation

```typescript
// Backend: JWT Utils
export const generateTokens = (payload: any) => {
  const accessToken = jwt.sign(payload, JWT_SECRET, { expiresIn: '15m' });
  const refreshToken = jwt.sign(payload, REFRESH_SECRET, { expiresIn: '7d' });

  return { accessToken, refreshToken };
};

// Frontend: Auto-refresh interceptor
this.client.interceptors.response.use(
  (response) => response,
  async (error) => {
    if (error.response?.status === 401) {
      const refreshToken = await this.getRefreshToken();
      if (refreshToken) {
        try {
          const newTokens = await this.refreshTokens(refreshToken);
          // Retry original request
          return this.client.request(error.config);
        } catch (refreshError) {
          this.logout();
        }
      }
    }
    return Promise.reject(error);
  }
);
```

## 📊 FLUX DE DONNÉES ET PROCESSUS MÉTIER

### Processus d'Inscription Utilisateur
1. **Saisie des informations** (Frontend)
   - Nom, email, téléphone, mot de passe
   - Validation côté client

2. **Envoi vers API** (Backend)
   - POST /auth/register
   - Validation des données (Zod)
   - Vérification unicité email/téléphone

3. **Création compte** (Base de données)
   - INSERT users avec is_verified=false
   - Génération et envoi OTP email

4. **Vérification OTP**
   - Utilisateur saisit code reçu
   - POST /auth/verify-email
   - Mise à jour is_verified=true

### Processus d'Achat de Ticket
1. **Sélection produit** (Frontend)
   - Choix type de ticket et quantité
   - Affichage prix total

2. **Initiation paiement** (API Payments)
   - POST /payments/initiate
   - Création transaction avec statut pending
   - Retour référence paiement

3. **Paiement mobile** (TMoney/Flooz)
   - Redirection vers plateforme paiement
   - Saisie PIN par utilisateur

4. **Polling statut** (Frontend)
   - GET /payments/status/:id toutes les 2s
   - Attente confirmation paiement

5. **Génération ticket** (Backend)
   - Création ticket avec QR code unique
   - Envoi confirmation email
   - Mise à jour solde si applicable

### Processus de Validation Ticket
1. **Scan QR code** (App Contrôleur)
   - Ouverture caméra
   - Décodage QR vers ID ticket

2. **Vérification** (API)
   - GET /tickets/:id/validate
   - Contrôles: validité, expiration, trajets restants
   - Mise à jour statut et décompte trajets

3. **Retour résultat** (App Contrôleur)
   - Affichage succès/échec
   - Sauvegarde historique local

### Synchronisation Temps Réel
1. **Action utilisateur** (Frontend/Admin)
   - Achat ticket, modification ligne, etc.

2. **Émission événement** (Backend)
   - Server-Sent Events (SSE)
   - Diffusion à tous les clients connectés

3. **Réception et mise à jour** (Frontends)
   - Écoute événements temps réel
   - Mise à jour automatique des écrans

#### Pattern Repository avec Pool de Connexions
**Méthode d'implémentation**:
```typescript
// Pool PostgreSQL réutilisable
const pool = new Pool({
  host: process.env.DB_HOST,
  port: parseInt(process.env.DB_PORT || '5432'),
  database: process.env.DB_NAME,
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  max: 20, // Pool de 20 connexions max
  idleTimeoutMillis: 30000
});

// Repository pattern avec gestion d'erreur
export class TicketRepository {
  static async create(ticketData: CreateTicketInput): Promise<Ticket> {
    const client = await pool.connect();
    try {
      await client.query('BEGIN');

      const result = await client.query(
        'INSERT INTO tickets (user_id, type, price) VALUES ($1, $2, $3) RETURNING *',
        [ticketData.userId, ticketData.type, ticketData.price]
      );

      await client.query('COMMIT');
      return result.rows[0];
    } catch (error) {
      await client.query('ROLLBACK');
      throw error;
    } finally {
      client.release(); // Retour au pool
    }
  }
}
```

#### Pattern de Cache Multi-niveaux
**Méthode d'implémentation**:
```typescript
// Frontend: Cache hiérarchique
class CacheManager {
  private memoryCache = new Map();
  private persistentCache = AsyncStorage;

  async get(key: string): Promise<any> {
    // Niveau 1: Mémoire (le plus rapide)
    if (this.memoryCache.has(key)) {
      return this.memoryCache.get(key);
    }

    // Niveau 2: Storage persistant
    const stored = await this.persistentCache.getItem(key);
    if (stored) {
      const data = JSON.parse(stored);
      this.memoryCache.set(key, data); // Remonte en mémoire
      return data;
    }

    return null;
  }

  async set(key: string, value: any): Promise<void> {
    // Double écriture pour cohérence
    this.memoryCache.set(key, value);
    await this.persistentCache.setItem(key, JSON.stringify(value));
  }
}
```

### INTÉGRATIONS EXTERNES

#### Intégration Paiements Mobile Money
**Méthode d'implémentation**: Webhook + Polling hybride

```typescript
// Pattern: Webhook avec fallback polling
export class PaymentService {
  async initiatePayment(paymentData: PaymentRequest): Promise<PaymentResponse> {
    // 1. Création transaction locale
    const transaction = await PaymentRepository.create({
      userId: paymentData.userId,
      amount: paymentData.amount,
      status: 'pending',
      provider: paymentData.provider // TMoney/Flooz
    });

    // 2. Appel API externe (TMoney/Flooz)
    const externalResponse = await this.callExternalAPI(paymentData);

    // 3. Configuration webhook + timeout
    this.setupWebhookTimeout(transaction.id, 300000); // 5 min timeout

    return {
      transactionId: transaction.id,
      redirectUrl: externalResponse.paymentUrl,
      pollUrl: `/payments/status/${transaction.id}`
    };
  }

  // Webhook receiver avec sécurité HMAC
  async handleWebhook(req: Request): Promise<void> {
    const signature = req.headers['x-webhook-signature'];
    const payload = JSON.stringify(req.body);

    // Vérification signature
    const expectedSignature = crypto
      .createHmac('sha256', WEBHOOK_SECRET)
      .update(payload)
      .digest('hex');

    if (signature !== expectedSignature) {
      throw new Error('Invalid webhook signature');
    }

    // Traitement asynchrone
    await this.processPaymentUpdate(req.body);
  }
}

// Frontend: Polling avec backoff exponentiel
class PaymentPoller {
  async pollPaymentStatus(transactionId: string): Promise<PaymentStatus> {
    let attempts = 0;
    const maxAttempts = 30; // 5 minutes max

    while (attempts < maxAttempts) {
      try {
        const status = await apiClient.get(`/payments/status/${transactionId}`);

        if (status.data.status !== 'pending') {
          return status.data; // Terminé (success/failed)
        }

        // Backoff: 2s, 4s, 8s, puis 10s constant
        const delay = Math.min(2000 * Math.pow(2, attempts), 10000);
        await this.sleep(delay);

        attempts++;
      } catch (error) {
        console.warn('Polling error:', error);
        await this.sleep(5000); // Retry dans 5s
      }
    }

    throw new Error('Payment polling timeout');
  }
}
```

```typescript
const performanceMiddleware = (req: Request, res: Response, next: NextFunction) => {
```

#### Validation Input avec Zod
**Méthode d'implémentation**: Schémas réutilisables

```typescript
// Schémas de validation centralisés
export const schemas = {
  register: z.object({
    name: z.string().min(2).max(50),
    email: z.string().email(),
    phone: z.string().regex(/^\+228\d{8}$/), // Format Togo
    password: z.string().min(8).regex(/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)/)
  }),

  login: z.object({
    email: z.string().email(),
    password: z.string().min(1)
  })
};

// Middleware de validation
const validate = (schema: z.ZodSchema) => {
  return (req: Request, res: Response, next: NextFunction) => {
    try {
      schema.parse(req.body);
      next();
    } catch (error) {
      if (error instanceof z.ZodError) {
        return res.status(400).json({
          success: false,
          error: 'Données invalides',
          details: error.errors.map(e => ({
            field: e.path.join('.'),
            message: e.message
          }))
        });
      }
      next(error);
    }
  };
};

// Usage dans les routes
router.post('/register', validate(schemas.register), AuthController.register);
```

- **Problème**: App mobile cassée en cas de perte réseau
- **Solution**: Cache local + retry automatique + fallback UI
- **Méthode**: Pattern Circuit breaker avec AsyncStorage

**4. Performance Admin avec Gros Volumes**
- **Problème**: Pagination lente avec milliers d'utilisateurs
- **Solution**: Pagination serveur + React Query + index DB
- **Méthode**: Cursor-based pagination

#### Structure Base de Données Complète
```sql
-- Tables principales avec relations
CREATE TABLE users (
  id SERIAL PRIMARY KEY,
  email VARCHAR(255) UNIQUE NOT NULL,
  phone VARCHAR(20) UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  name VARCHAR(100) NOT NULL,
  role user_role DEFAULT 'user',
  is_verified BOOLEAN DEFAULT FALSE,
  is_suspended BOOLEAN DEFAULT FALSE,
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW()
);

CREATE TABLE tickets (
  id SERIAL PRIMARY KEY,
  user_id INTEGER REFERENCES users(id),
  ticket_code VARCHAR(50) UNIQUE NOT NULL,
  type VARCHAR(50) NOT NULL,
  price_paid_fcfa INTEGER NOT NULL,
  status ticket_status DEFAULT 'active',
  qr_code TEXT NOT NULL,
  expires_at TIMESTAMP,
  created_at TIMESTAMP DEFAULT NOW()
);

-- Index pour performances
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_tickets_user_id ON tickets(user_id);
CREATE INDEX idx_tickets_status ON tickets(status);
CREATE INDEX idx_tickets_created_at ON tickets(created_at);
```
